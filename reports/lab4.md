## 三、问答题

### 1. easy-fs 中 root inode 的作用及损坏后果

root inode 是根目录的索引节点，编号为 0。`EasyFileSystem::create` 创建它，`EasyFileSystem::root_inode` 根据编号定位它。它记录根目录的类型、大小和数据块索引；目录数据块中的 `DirEntry` 保存文件名与 inode 编号的对应关系。查找文件时，`Inode::find` 先读取这些目录项，再定位目标文件的 inode。

本实验的 easy-fs 使用单层目录，文件查找依赖根目录。如果 root inode 的大小或块索引损坏，目录项可能无法完整读取或被错误解释，导致文件名查找失败；类型损坏还可能触发目录类型断言。文件 inode 和数据块可能仍保存在磁盘中，但正常的文件名访问路径已经受损，需要修复根目录元数据及目录项映射。

### 2. pipe 的实际应用

在 Linux shell 中，可以将 `cat` 的输出交给 `wc`，统计文件中的换行符数量：

```bash
cat file.txt | wc -l
```

shell 创建管道，使 `cat` 的标准输出连接写端，`wc` 的标准输入连接读端，并关闭各进程不用的管道端。`cat` 读取文件后写入管道；`wc` 读取并计数，直到写端全部关闭且数据读完，再输出结果。末尾没有换行符的最后一段文本不会额外增加 `wc -l` 的计数。

本章的 `ch7b_pipetest` 用一条管道把父进程的字符串传给子进程；`ch7b_pipe_large_test` 则用一条管道发送 3000 字节数据，再用另一条管道回传求和结果。

### 3. 更易用的多进程通信机制

可以设计由内核管理的消息队列，每个接收进程注册一个邮箱，发送者通过邮箱编号发送消息。这样进程只需知道目标邮箱，无需为每一对进程创建管道。

接口可设计为：

```rust
mailbox_create() -> MailboxId
send(destination: MailboxId, data: &[u8]) -> Result<usize>
recv(mailbox: MailboxId, buffer: &mut [u8]) -> Result<(Pid, usize)>
```

内核维护邮箱表，每个邮箱包含所有者、消息队列、容量及等待队列。消息保存发送者 PID、长度和内容。`send` 将用户数据复制到目标队列，唤醒接收者；`recv` 取出一条消息并复制到用户缓冲区。队列空时接收者进入等待队列，队列满时发送者等待容量释放。队列操作在锁内完成，进入调度前释放锁。

若有 N 个进程，每个进程一个邮箱只需维护 N 个接收端。多个发送者可向同一邮箱投递，回复时使用消息中的发送者身份定位其邮箱。内核检查访问权限，进程退出时释放所属邮箱并通知等待者。
