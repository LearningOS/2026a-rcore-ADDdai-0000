## 三、问答题：stride 算法深入

### 1. 使用 8 位无符号整数时，下一次实际会选择谁？

设两个进程的 pass 都为 10，p1.stride = 255，p2.stride = 250。当前应选择 p2；它执行后，数学意义上的累计值是 260，因此下一次应选择累计值为 255 的 p1。

但在 8 位无符号整数的环绕运算下，260 会变成 `260 % 256 = 4`。如果继续用普通整数大小比较，就会认为 `4 < 255`，再次选择 p2，导致调度顺序错误。

因此，仅让加法在溢出时回绕还不够，比较规则也必须识别回绕关系。如果使用开启溢出检查的普通加法，则还可能直接触发 panic；这里讨论的是题设中的回绕情形。

### 2. 为什么 STRIDE_MAX − STRIDE_MIN ≤ BigStride / 2？

令 `B = BigStride`。优先级至少为 2，因此每次增加的步长满足：

```text
pass = B / priority ≤ B / 2
```

考虑一组从 stride = 0 开始、持续参与调度的进程，并且不发生整数溢出。

初始时最大值和最小值相同，差为 0。假设某次调度之前，最小值为 m，最大值不超过 `m + B/2`。

本次只更新一个最小值进程。它增加的 pass 不超过 `B/2`，所以更新后的值也不超过 `m + B/2`；其他进程不变，仍在这个上界以内。同时没有任何值变小，新最小值至少为 m。因此更新后的最大值与最小值之差仍不超过 `B/2`。

由初始条件和以上推导，可知该界限在后续调度中成立。该论证针对上述固定调度集合；运行过程中任意插入 stride 为 0 的新进程，不能直接沿用这一界限。

### 3. 如何在溢出时比较 Stride，并使 BinaryHeap 返回真正最小的进程？

可以使用环绕减法，将差值解释为有符号整数。在两个累计值的真实距离小于 u64 整数范围一半的前提下，差值的符号可以判断其先后关系。

Rust 的 `BinaryHeap` 默认弹出比较意义上的最大值，所以还需要反转比较顺序，使累计值较小的进程具有较大的排序结果。题目要求补全的 `partial_cmp` 可以写为：

```rust
impl PartialOrd for Stride {
    fn partial_cmp(&self, other: &Self) -> Option<Ordering> {
        let diff = self.0.wrapping_sub(other.0) as i64;
        Some(diff.cmp(&0).reverse())
    }
}
```

例如，用 8 位数类比：累计值 260 存为 4，而另一个累计值为 255。环绕差 `4 - 255` 得到 5，说明 4 所表示的累计值在 255 之后；反转排序后，堆会优先取出 255。

题目假设两个 Stride 不相等，因此不需要处理相等输入；若实际使用 `BinaryHeap<Stride>`，还必须实现与上述比较一致的 `Ord`、`Eq` 和 `PartialEq`。同时必须保持半圈范围内的比较前提，否则单凭回绕后的数值无法唯一判断先后顺序。

本次代码使用就绪队列线性扫描，没有使用 BinaryHeap，因此不反转比较顺序，而是通过以下条件选出更小的累计值：

```rust
(stride.wrapping_sub(min_stride) as isize) < 0
```

在本实验的 RV64 平台上，usize 和 isize 都是 64 位。选中进程后使用 `wrapping_add` 更新累计值；步长计算使用 `(BIG_STRIDE / priority).max(1)`，避免极大的优先级使整数除法结果为 0。
